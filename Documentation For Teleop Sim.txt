1. GUI SAYS "NOT CONNECTED TO CARLA" WHILE CARLA IS RUNNING
--------------------------------------------------------------------------
Symptom:
  CARLA was open, but AUTOSIM showed "NOT CONNECTED TO CARLA", black
  cameras, and buttons that did nothing.

Cause:
  The carla Python package was not installed in the Python that runs
  AUTOSIM. AUTOSIM shows the same "not connected" message for any
  connection failure. The real reason is printed in the terminal just
  above the line "[experiment] WARNING: no connection to CARLA".

  The three possible failures (autosim/simulation_carla.py, connect()):
    a) carla package not installed           <- this was our problem
    b) networkx / shapely missing (navigation agents fail to load)
    c) server does not answer at 127.0.0.1:2000 within 30 s
       (CARLA still loading, wrong port, firewall, CARLA on another machine)

How to check:
  python --version
  python -c "import carla; print(carla.__file__)"
  -> We got "ModuleNotFoundError: No module named 'carla'".

Fix:
  python -m pip install carla==0.9.15
  python -m pip install -r requirements.txt
  python -c "import carla; print(carla.__file__)"   (now prints a path)

Notes:
  - Use "python -m pip", not plain "pip", so the package installs into
    the same Python that runs AUTOSIM.
  - The carla package version must match the CARLA server version.
  - The README says the Windows wheel targets Python 3.7. That is only
    true of the wheel shipped inside the CARLA folder. PyPI has Windows
    packages for Python 3.7, 3.8, 3.9 and 3.10, so 3.10 works.
  - Success looks like this in the terminal:
    [carla] Connected to CARLA 0.9.15 at 127.0.0.1:2000.

Run command:
  python -m autosim --scenarios scenarios/example_battery.csv --participant TEST
  (Start CARLA first and wait until the map has fully loaded.)

2. AV DOES NOT FOLLOW THE ROUTE / CRASHES INTO A TREE ON RESUME AV
--------------------------------------------------------------------------
Symptom:
  The route drawn on the map did not match where the car was. The car
  started off in the wrong direction. On Resume AV it left the road and
  crashed into a tree.

Cause:
  CARLA reports a newly spawned car at location (0, 0, 0) facing yaw 0
  until the simulation has advanced one tick. AUTOSIM planned the route
  immediately after spawning the car, so:
    - the route started at the road nearest the map origin, not at the car
    - the starting push went along the map's x-axis, not along the lane
    - the AV drove off the road trying to reach the misplaced route
  Obstacles placed relative to the route were misplaced for the same reason.

Fix (autosim/simulation_carla.py, _spawn_ego, around line 562):
  After these lines:
        self.ego = ego
        self.spawned.append(ego)
  add:
        self.world.wait_for_tick()

Result: confirmed working. The route starts under the car and the AV
follows it.

3. AV TURNS SHARPLY AND CRASHES ON RESUME AV AFTER MANUAL CONTROL
--------------------------------------------------------------------------
Symptom:
  After driving in Manual Control and pressing Resume AV, the car made
  a sharp right turn and crashed instead of continuing on its route.

Cause:
  The self-driving agent keeps a list of upcoming road points to steer
  toward. That list is not updated during manual driving. Resume AV
  sends two steps (autosim/session.py, resume_autonomy):
    1) turn manual control off  -> car goes to the "holding" state
    2) resume autonomy          -> rebuilds the list only if the car is
                                   still in manual mode
  By step 2 the car is no longer in manual mode, so the list was never
  rebuilt. The agent steered toward old points behind or beside the car.

Fix (autosim/simulation_carla.py, set_manual_control, around line 406):
        elif self.mode == DrivingMode.MANUAL:
            self.mode = DrivingMode.HOLDING
            self._replan_from_here()          <- added

Expected behavior:
  The car continues from the nearest point on its original route. If
  you changed lanes manually, it merges back into the route's lane on
  its own.

4. AV IGNORES STOP SIGNS AND DOES NOT YIELD  (OPEN, NOT FIXED)
--------------------------------------------------------------------------
Symptom:
  In autonomous mode the car drives through stop signs and does not
  yield at intersections.

Cause:
  Not a bug in our changes. AUTOSIM drives the car with CARLA's built-in
  BasicAgent (autosim/third_party/carla_agents/). Its own description
  says it "respects traffic lights and other vehicles, but ignores stop
  signs". It has an ignore_stop_signs setting, but nothing reads it.
  CARLA's BehaviorAgent does not handle stop signs either.

  What the AV handles now:
    Traffic lights ............................ yes
    Car directly ahead in its lane ............ yes
    Pedestrians in its lane ................... yes (AUTOSIM adds this)
    Stop signs ................................ NO
    Yielding / right of way at junctions ...... NO

Possible fix (to add in autosim/simulation_carla.py):
  a) Stop signs (simpler): find the stop zone ahead on the route, stop
     fully, wait a few seconds, then go.
  b) Yielding (harder): before entering a junction, check for cars
     coming from other directions and wait for a gap.
  Add on/off switches in settings.py.

Decision needed:
  Should the AV always obey these rules, or should each scenario be
  able to turn them off (e.g. a CSV column), so the AV can break a
  rule on purpose for the operator to catch? Suggested default: stop
  signs on, with a switch to turn them off.

2. AV PULLS OVER AT THE ROUTE END AND DROPS OFF A PASSENGER
--------------------------------------------------------------------------
Old behavior (problem):
  - The AV only started pulling over after its planned route had run
    out, while still at full speed.
  - With no route left, it could not move to the rightmost lane. It
    drove about 28 m past the end, in whatever lane it was in, and
    stopped there, possibly in a middle lane or inside an intersection.
  - No passenger got out. The only route-end pedestrian was a "next
    customer" walking up to the car (autosim/session.py,
    _on_route_complete). That pedestrian is still there.

New behavior:
  1) Every route is extended so its last 20 m are clear of
     intersections, so a route never ends inside one.
  2) 40 m before the end, and only once the car is past the last
     intersection, the AV starts pulling over: moves to the rightmost
     lane, eases toward the curb or shoulder, and slows to 6 mph. It
     still stops for pedestrians crossing in front.
  3) It stops at the end of the route and turns the hazard lights on.
  4) The rear-right (curb-side) door opens (on car models that support
     opening doors). A passenger appears beside it, walks to the
     sidewalk and about 15 m along it, then disappears. The door closes
     after 3 s.
  5) "Route complete" appears only after the passenger is gone.

  On screen: driving mode "Passenger exiting" and the alert "Passenger
  is getting out" while this happens.
  In the data: new event-log entries passenger_dropoff_started and
  passenger_dropoff_complete (documented in docs/DATA.md).
  Edge cases:
    - The passenger touching the car does NOT count as a collision.
    - If the operator interrupts the pull-over (E-STOP, manual control,
      a task stop) and then presses Resume AV, the AV plans the
      pull-over again from where it is.
    - Only one passenger is dropped off per scenario.
    - If there is no room for the passenger, the drop-off is skipped
      (warning in the terminal) and the route completes.

Files changed:
  autosim/simulation_carla.py  pull-over at the route end, route
                               extension past intersections, passenger
                               drop-off
  autosim/simulation.py        new driving mode DROPPING_OFF
  autosim/session.py           log events and the on-screen alert
  autosim/settings.py          new settings (below)
  docs/DATA.md                 new log events

Settings (autosim/settings.py), defaults:
  ROUTE_END_PULL_OVER_START_METERS        40    start pulling over this far before the end
  ROUTE_END_CLEAR_OF_JUNCTION_METERS      20    last stretch of route clear of intersections
  ROUTE_END_MAX_EXTENSION_METERS          60    how far a route may be extended for that
  DROP_OFF_PASSENGER_AT_ROUTE_END         True  set False to turn the drop-off off
  PASSENGER_WALK_SPEED_MPS                1.3
  PASSENGER_WALK_AWAY_METERS              15
  PASSENGER_MAX_SIDEWALK_DISTANCE_METERS  6     farther: passenger walks straight out instead
  PASSENGER_DOOR_OPEN_SECONDS             3
  PASSENGER_DROPOFF_TIMEOUT_SECONDS       30    remove a passenger who gets stuck
  Also relevant: PULL_OVER_SPEED_MPH (6). Raise it if the final crawl
  to the curb feels too slow.

Testing:
  - python -m pytest: 25 passed (these tests do not cover the CARLA code).
  - Claude ran the new logic against a stand-in for CARLA: intersection
    extension, no pull-over inside an intersection, stop, hazards,
    door open/close, passenger walking away and being removed, no false
    collision, "Route complete" only after the passenger is gone, and
    no second passenger after Resume AV. All passed.
  - NOT yet tested in real CARLA.

How to test in CARLA:
  git switch main
  git pull
  (start CARLA and wait for the map to load)
  python -m autosim --scenarios scenarios/example_battery.csv --participant TEST
  Let a scenario drive to the end of its route and check:
    [ ] The car stops at the right curb, not in a middle lane or intersection.
    [ ] The passenger gets out on the right, walks onto the sidewalk and
        away, and disappears.
    [ ] "Route complete" appears afterwards.
    [ ] No "Collision detected" alert during the drop-off.
    [ ] The log (data/<participant>_<date>_<time>/) has
        passenger_dropoff_started and passenger_dropoff_complete.
    [ ] Optional: press E-STOP during the pull-over, then Resume AV. It
        should pull over again and drop off only one passenger.
